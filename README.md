# Latticework

A single-file personal knowledge app: books to ideas to mental models to connections,
plus a Find feature that matches a described situation against the whole library.

Live at: https://latticework-psi.vercel.app/

## What's here

- `index.html` — the built, deployable app. This is the file Vercel serves as-is; there is
  no build step. It is generated by concatenating everything in `src/` (see below).
- `src/` — the source of truth. `build.py` concatenates `data*.js` (books and ideas),
  `*_links.js` (cross-book connection passes), and `app.js` into `shell.html`'s
  `/*__DATA__*/` and `/*__APP__*/` placeholders to produce the built file:

  ```
  cd src && python3 build.py
  ```

  This writes `/home/claude/pk/latticework.html` by default (see the path in `build.py`);
  copy or symlink that to `index.html` at the repo root to redeploy.

- `src/check.js` — a Node validation script (idea counts, duplicate ids, dangling
  connections, unused mental models, word-count bands). Run with `node src/check.js`
  before shipping any content change.
- `tests/` — Playwright regression scripts. Run against a local Chromium build; see each
  file's `executablePath` for the expected binary location.
- `icon-512.png`, `og-image.png` — source images for the home-screen icon and the social
  link-preview card, already inlined into `shell.html` as data URIs.

## State model

All user data (saved/learned/applied ideas, notes) lives in the browser's own
`localStorage`, keyed by a locally-entered email or a guest flag. There is no backend and
no real authentication: "signing in" only labels which local data bucket to use. This means
each device has its own independent, private data with no setup, and nothing is ever sent
anywhere.

## Deploying

This repo is connected to a Vercel project as a static site (no framework, no build
command). Pushing to `main` triggers a redeploy automatically.
